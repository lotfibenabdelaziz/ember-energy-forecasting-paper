# Ember Energy Demand Forecasting
**IEEE Paper | End-to-End ML Pipeline**

> Per-country electricity demand forecasting (2025–2030) for **Tunisia, Austria,
> Germany, Egypt, Canada, France, and Kuwait** using the
> [Ember](https://ember-climate.org/data/data-tools/data-explorer/) annual energy dataset.
>
> Models: Ridge · RandomForest · XGBoost · MLP · TCN · N-BEATS · TFT (PyTorch)

> `val_end=2020`, `test_end=2024`.

## Quick Start

Requires [uv](https://docs.astral.sh/uv/) (`curl -LsSf https://astral.sh/uv/install.sh | sh`) —
the Makefile manages the virtual environment for you; you don't run `uv` directly for normal use.

```bash
# 1. Clone & install
git clone https://github.com/lotfibenabdelaziz/ember-energy-forecasting.git
cd ember-energy-forecasting
make install             # uv venv + uv pip install -r requirements.txt

# 2. Configure environment
cp .env.example .env
# Edit .env: set CSV_PATH, OPENAI_API_KEY (optional)

# 3. Place your data
cp /path/to/yearly_full_release_long_format.csv data/raw/

# 4. Start MLflow UI (separate terminal)
make mlflow-ui          # → http://localhost:5000

# 5. Run full pipeline (smart cache: skips unchanged steps)
make run

# 6. Start REST API
make api-run            # → http://localhost:8000/docs
```

**Configuration:** `params.yaml` is the single source of truth for pipeline
parameters (countries, train/val/test splits, model hyperparameters) —
`src/config.py` reads it. `.env` is only for deployment/secret values (paths,
ports, API credentials) that legitimately differ per environment; it does
not duplicate anything in `params.yaml`.

## Data Modeling — Staging Warehouse

The raw Ember release is a long/EAV table (`Area, Year, Subcategory, Value`).
`step02_preprocessing.py` pivots it into a wide feature table for modeling —
that's the right shape for pandas/scikit-learn and isn't changing. What
`src/staging.py` adds is an **optional** star-schema staging layer in front
of that:

```
fact_energy_measurement ──┬── dim_country
                           ├── dim_year        (year, split_label)
                           └── dim_subcategory
```

`dim_year.split_label` (`train` / `val` / `test` / `forecast`) makes the
train/val/test boundary a **queryable column** instead of a convention every
downstream script has to remember to respect — a `SELECT ... WHERE
split_label = 'train'` is leak-safe by construction. This is the same
discipline `step02_preprocessing.py` now enforces in code (imputation,
winsorization bounds, and feature-selection are all fit on `Year <=
train_until` only, never the reverse) — the warehouse just gives you a
second, independent way to enforce and audit it.

Backend: **SQLite** by default (Python stdlib, zero extra dependency).
**DuckDB** is used automatically if installed (`make staging-install`) —
better suited to analytical queries, though at this dataset's size (~1,200
fact rows) either is instant. This is deliberately *not* a Data Vault or a
server-backed warehouse — that would be over-engineering for a single-source,
annual, few-hundred-row dataset; a star schema sized to the actual data is
the right scope here.

```bash
make staging-build     # builds warehouse/ember.db from data/raw/*.csv
make staging-query     # prints the leak-safe train-split view

# Optional: source step02_preprocessing.py directly from the warehouse
# instead of the CSV (same output either way):
python src/step02_preprocessing.py --source warehouse --db_path warehouse/ember.db
```

See `warehouse/schema.sql` for the full DDL and rationale.

## Smart Caching

`pipeline.py` hashes **inputs** (script + data files + params) before each step.
If the hash matches the stored value and all outputs exist — the step is skipped.

```bash
make run                           # smart run — skips unchanged steps
make run-force                     # re-run everything regardless of cache
make cache-status                  # show cached steps
make cache-clear                   # wipe entire cache
make cache-invalidate-modeling     # force only modeling to re-run
```

Cache stored in `.cache/pipeline/cache.json` (git-ignored).
